# mm-catalog-api

## Каталог кромок

CRUD кромок и справочников производителей, толщин и единиц продажи расположен под `/api/for-admin/edges`. Список кромок вместе с фильтрами возвращается одним запросом `GET /api/for-admin/edges/compact`. Изображения загружаются через административный API кромок и читаются через `/api/edges/images/{fileGuid}`. Общий порядок материалов и кромок, перемещение стрелками и миграция `20261025151403_AddEdgeSortOrder` описаны в [CATALOG_ORDER.md](catalog-api/docs/CATALOG_ORDER.md).

Контракты и правила описаны в [docs/EDGES_API.md](catalog-api/docs/EDGES_API.md). Миграция `20261022200130_AddEdgesCatalog` создаёт шесть отдельных таблиц кромок без тестовых данных. Миграцию применяет пользователь вручную; перед применением нужно проверить ожидающие миграции и целевую БД. Изменения не подключают прототип Front к API автоматически.

Сборка без обращения к NuGet: `dotnet build catalog-api/catalog-api.slnx --no-restore`. Зависимости для этого этапа не менялись.

## Порядок маркировок связей

Маркировки возвращаются по `orderByCol`, затем `id` в списке `/api/for-admin/relations/markings` и `filters.markings` компактного списка связей. Поле `orderByCol` также есть в карточке. Новая маркировка добавляется в конец; переименование сохраняет её позицию.

`POST /api/for-admin/relations/markings/change-order-col` принимает `{ "id": 1, "direction": "UP" }` или `"DOWN"` и возвращает `{ "success": true }`. Переставляются соседи полного списка, независимо от фильтра клиента; на границе возвращается `400`. После изменения клиент перечитывает список и инвалидирует кэш связей. Создание и перемещение выполняются через EF Serializable с существующим повтором конфликтов. Перемещение записывается в историю как Update маркировки; для tester действует стандартный пропуск истории.

Миграция `20261025173751_AddRelationMarkingSortOrder` добавляет `catalog.relation_markings.order_by_col` с `NOT NULL DEFAULT 0` и индексом `(order_by_col, id)`. Её применяет пользователь вручную до запуска новой версии API. Существующие маркировки получают нулевые значения и отображаются по Id, а не по прежнему алфавитному порядку. Первое успешное перемещение нормализует позиции в `1..N`, сохраняя относительный порядок остальных записей. Миграция не содержит SQL переноса данных; откат удаляет только новое поле и индекс.

## Стоимость кромки

У кромки есть обязательное поле `price` — стоимость за погонный метр в рублях. Оно доступно при создании и изменении, в карточке, компактном списке, Excel-выгрузке и истории. Отсутствие поля и `null` отклоняются; ноль допустим. Контракт и миграции `20261026093511_AddEdgePrice` / `20261026100653_RequireEdgePrice` описаны в [EDGE_PRICES.md](catalog-api/docs/EDGE_PRICES.md).

Начальная загрузка берёт эффективную цену «Мебельщик» из ВЕК. [Сверка и результаты переноса](catalog-api/docs/edge-prices-2026-10-26/result.md) содержат источники, решения по расхождениям и проверки.

По последующему указанию пользователя 26.10.2026 M703/M715/M801 получили стоимость 0, а миграция `RequireEdgePrice` применена к `mm`. Все 396 стоимостей заполнены; `PriceSpecified` удалён. [Проверка обязательной стоимости](catalog-api/docs/edge-prices-required-2026-10-26/result.md).

## Удаление кромки со связями

`DELETE /api/for-admin/edges/{id}` отклоняет удаление кромки при любой связи с материалом: `400 ProblemDetails` с сообщением «Кромка связана с материалами. Сначала снимите все связи с материалами.». Сначала нужно удалить все её связи; после этого кромка удаляется обычным способом вместе с изображениями.

Миграция `20261026062250_RestrictLinkedEdgeDeletion` меняет FK `material_edge_links.edge_id → edges.id` с Cascade на Restrict. Пользователь применяет её вручную. Эта защита БД закрывает гонку появления связи между проверкой и удалением: нарушение именно этого FK преобразуется в то же сообщение `400`, а не удаляет связь каскадно. Проверка без применённой миграции не даёт полной защиты от такой гонки. Поведение удаления материала и очистки его связей не меняется.

## Документация API

Настраиваемая выгрузка материалов и кромок в `.xlsx`: [контракт экспорта](catalog-api/docs/EXCEL_EXPORT_API.md).

`GET /api/for-vek-lk/materials` для авторизованного пользователя ЛК возвращает `{ "items": [{ "id", "name", "article", "categoryId", "count", "image" }], "categories": [{ "id", "name" }] }` для выбора материала в раскрое. Включаются материалы, у которых и у категории `hideInLk=false`, независимо от `hideOnSite`; категории без доступных материалов отсутствуют. `name` формируется как «тип материала → название → толщина в мм → высота×ширина плиты → производитель», например `ЛДСП Айрон Рок U9712 LF 16 мм 2750×1830 Увадрев`. Дробная толщина выводится без лишних нулей, с десятичной запятой. Материалы с нулевым остатком остаются в выдаче. Категории упорядочены по `orderByCol`, затем `id`; материалы — в порядке категорий, внутри категории по собственным `orderByCol` и `id`. `image` содержит GUID миниатюры 240 px, при её отсутствии — 480 px, иначе null; изображение доступно через `GET /api/materials/images/{guid}`. Все Id принадлежат Catalog API. В профиле Vek запрос требует cookie `VekExpressCookie`; фронт передаёт её через `credentials: "include"`. Без действительной cookie возвращается 401.

`GET /api/for-vek-lk/materials/{id}` возвращает только `{ "id", "name" }` выбранного материала с теми же правилами авторизации, видимости и форматом имени. Неизвестный материал, скрытый материал или материал скрытой категории возвращает `400 ProblemDetails`.

`hideInLk` — отдельный признак материала и категории, доступный в административных запросах создания/обновления, карточках и списках. У материалов он также копируется при клонировании и доступен в Excel-экспорте. `true` означает «скрыт в ЛК», как у `hideOnSite`; значение по умолчанию — `false`. При сохранении записывается значение поля из модели. `hideInLk=true` у категории скрывает её материалы в ЛК, не меняя собственные флаги этих материалов; снятие признака возвращает только материалы с `hideInLk=false`. Настройки сайта остаются независимыми.

Все материалы каталога предназначены для раскроя. Поля `applicableToCutting`, `applicableToPvhFacades`, `applicableToEnamelFacades`, их компактные варианты `cu`/`pv`/`en`, enum `MaterialCalculatorEnum` и query-параметр `calculators` удалены из актуальных контрактов.

Перед запуском обновлённого API пользователь применяет миграцию `20261030105853_AddLkVisibilityAndRemoveMaterialApplicability`. Она добавляет `hide_in_lk=false` для всех существующих материалов и категорий и удаляет три прежних столбца назначения. При откате эти столбцы создаются со значением `false`; прежние значения не восстанавливаются.

`GET /api/for-admin/materials/compact` возвращает в поле `im` GUID миниатюры 240 px, при её отсутствии — 480 px, иначе null. Оригинал не подставляется. Список читает только GUID; файл можно лениво получить через публичный `GET /api/materials/images/{guid}` с годовым HTTP-кешем и ETag по GUID.

Поле `el` компактного списка содержит внешнюю ссылку материала или null. `PUT /api/for-admin/materials/{id}/external-link` с `{ "externalLink": "https://example.com/material" }` меняет только эту ссылку; null или пустая строка удаляют её. Разрешены полные HTTP(S)-ссылки до 250 символов. Ответ — `{ "success": true }`.

`POST /api/for-admin/materials/{id}/clone` без тела возвращает `{ "newMaterialId": 123 }`. Копия получает название «исходное название (Копия)» и место сразу после исходного материала в общем порядке. Копируются все свойства, изображения с новыми GUID, связи с кромками и их маркировки; общие кромки и справочники остаются прежними. В истории создаётся одна запись Create с источником копии. Для названия длиннее 250 символов после добавления суффикса возвращается 400. Изменения схемы БД не требуются.

`ApiDoc:Enabled` включает OpenAPI, Scalar и Swagger UI. В `appsettings.json` документация выключена, в `appsettings.Development.json` включена. Если флаг отсутствует, документация недоступна. Для включения в другом окружении задайте `ApiDoc__Enabled=true` и перезапустите API.

## Подключения к БД и общая авторизация

`DbConnString` задаёт подключение к данным Catalog API. `DataProtectionDbConnString` задаёт отдельное подключение к общему хранилищу ключей Data Protection, которыми защищаются cookie авторизации; сами cookie в этой БД не хранятся. Строки подключения независимы: хост, база, пользователь и остальные параметры могут различаться.

Для общей авторизации с Accounts API должны совпадать хранилище ключей, имя приложения Data Protection (`Cookie.CookieName(Cookie.DomainName)`), имя cookie и её домен. `DataProtectionDbConnString` должен указывать на хранилище Accounts API, выдавшего cookie.

Оба подключения задаются в `appsettings.json` и `appsettings.Development.json` либо одноимёнными переменными окружения. После изменения строк подключения перезапустите API; перекомпиляция не требуется.

`Authentication:Provider` выбирает только провайдер БД ключей: `Accounts` — прежний PostgreSQL по умолчанию, `Vek` — MS SQL ВЕК. Cookie-авторизация и существующие проверки ролей остаются общими. ВЕК выпускает совместимую cookie; PostgreSQL с данными каталога остаётся отдельным подключением.

Catalog API использует `Microsoft.Data.SqlClient 7.1.1` без необязательного пакета Azure-аутентификации. `SatelliteResourceLanguages=en` исключает языковые сборки зависимостей из build/publish; русские сообщения самого API сохраняются. Публикацию выполняйте в чистую папку, чтобы в ней не оставались файлы предыдущих зависимостей.

## Публикация Main и Vek

Два профиля публикации в папку можно выбрать в IDE или запустить из корня репозитория:

```bash
dotnet publish catalog-api/Catalog.Api/Catalog.Api.csproj -c Release --no-restore -p:PublishProfile=Main
dotnet publish catalog-api/Catalog.Api/Catalog.Api.csproj -c Release --no-restore -p:PublishProfile=Vek
```

| Профиль | Папка результата | Источник опубликованного `appsettings.json` |
| --- | --- | --- |
| [Main](catalog-api/Catalog.Api/Properties/PublishProfiles/Main.pubxml) | `catalog-api/Catalog.Api/bin/Publish/Main/` | `appsettings.json` |
| [Vek](catalog-api/Catalog.Api/Properties/PublishProfiles/Vek.pubxml) | `catalog-api/Catalog.Api/bin/Publish/Vek/` | `appsettings.Vek.json` |

В папке `Vek` опубликованный `appsettings.json` содержит точную копию `appsettings.Vek.json`. Это полный конфиг, а не дополнение к основному. Редактируйте настройки ВЕК в этом JSON и повторяйте команду.

Окружение приложения остаётся `Production` по умолчанию; задавать `ASPNETCORE_ENVIRONMENT=Vek` не требуется. Исходные JSON и конфигурация локальной сборки не меняются. Обычный publish без профиля использует основной `appsettings.json`; `appsettings.Development.json` и отдельный `appsettings.Vek.json` не публикуются. При повторной публикации основной файл настроек перезаписывается выбранным вариантом.

## Диагностика локальной разработки

### Сборка и форматирование в sandbox

Если `dotnet build` или `dotnet format` зависает после запуска либо завершается ошибкой Roslyn `named pipe` / `Permission denied`, проверьте вывод и принадлежность процесса. Остановите только собственный зависший процесс и повторите команду через штатное разрешение на выполнение вне sandbox. Не останавливайте процессы пользователя и не меняйте постоянные порты или `hosts` ради проверки.

Обязательную проверку `dotnet format catalog-api/catalog-api.slnx --verify-no-changes --no-restore` выполняйте из корня репозитория. Если она обнаруживает ранее существовавшие нарушения вне задачи, отдельно проверьте изменённые файлы через `--include` и сообщите об ограничении общей проверки. Не правьте подмодуль `core` ради посторонних ошибок форматирования без предусмотренного правилами согласования.

### Ошибка PostgreSQL 42703 после переименования поля

Ошибка `42703` о недостающем переименованном столбце может означать, что приложение обновлено, а схема БД ещё нет. Сначала сверяйте подключение с нужным окружением и просматривайте историю через `dotnet ef migrations list --project catalog-api/Catalog.Database/Catalog.Database.csproj --context CatalogDbContext`. У design-time factory собственная строка подключения: одно значение `ASPNETCORE_ENVIRONMENT=Development` не гарантирует выбор нужной БД. Сравнивайте настройки без вывода секретов.

Применяйте миграции согласно `AGENTS.md`: по умолчанию это делает пользователь вручную. Агент может отступить от запрета только по явному разрешению пользователя для конкретных миграций и БД; перед применением проверьте весь список ожидающих миграций и задайте точную целевую миграцию. После применения проверьте историю и повторите затронутый запрос чтения. Не переписывайте исторические миграции и не создавайте недостающие столбцы вручную.

## Размеры материала

Материал ссылается на формат плиты через `sheetSizeId`. Поля `kvM` и `perimetrM` удалены из модели, административных запросов создания/обновления и ответов API. `GET /api/for-calculate/materials/{id}` возвращает `{ "id", "width", "height", "price", "name", "article" }`; ширина и высота берутся из формата плиты и выражены в целых миллиметрах, `price` — стоимость листа в рублях. `name` использует общий шаблон полного имени для ЛК: тип материала, название, толщина, формат плиты и производитель.

Миграция `20261019214841_RemoveMaterialMeasurements` удаляет столбцы `kv_m` и `perimetr_m` из `catalog.materials`. Её применяет пользователь вручную после подготовки потребителей нового контракта. При откате миграция восстанавливает столбцы с нулями, а не прежние значения. До обновления модели БД создание материалов новой версией API не проверяется.

## Стоимость для Calculate API

`GET /api/for-calculate/edges/price?materialId=123&thickness=0.4` возвращает `{ "price": 25.50, "article": "M-123" }` — стоимость кромки за погонный метр в рублях и её артикул. Толщина передаётся значением в миллиметрах, а не Id справочника. Выбирается связь указанного материала с кромкой нужной толщины и маркировкой «Век ЛК». Если подходящей связи нет или их несколько, возвращается `400 ProblemDetails`; ошибочные параметры и неизвестный материал также отклоняются. Нулевая цена найденной кромки допустима. Endpoint доступен анонимно, как получение одного материала для расчёта.

Количество листов, расход кромки и технологический запас рассчитывает Calculate API. Миграции для новых контрактов Catalog API не требуются; поле стоимости кромки должно уже присутствовать в БД.
