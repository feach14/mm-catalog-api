# Справочник толщин материалов

`MaterialThickness` хранит `Id`, обязательное `Name` (до 100 символов) и `Value` в миллиметрах. Материал связан обязательным `MaterialThicknessId`. По `Value` создан уникальный индекс. Дополнительных CHECK constraints нет. Положительность и конечность значения, название и дубликаты проверяются FluentValidation. Запрошенная связь имеет запрет каскадного удаления; использование толщины перед удалением также проверяется в handler.

## API

- `GET /api/materials/thicknesses`: `{ "items": [{ "id": 1, "name": "4,1 мм", "value": 4.1 }] }`.
- `GET /api/materials/thicknesses/{id}`: `{ "id": 1, "name": "4,1 мм", "value": 4.1 }`.
- `POST /api/admin/materials/thicknesses`: тело `{ "name": "Тонкая плита", "value": 4.1 }`.
- `PUT /api/admin/materials/thicknesses/{id}`: такое же тело; изменение названия или значения отражается на связанных материалах.
- `DELETE /api/admin/materials/thicknesses/{id}`: удаление неиспользуемой толщины.

Чтение публичное; изменения доступны административным ролям. Действия журналируются по общим правилам каталога. Тестер не создаёт событий истории.

При создании и изменении материала требуется `thicknessId`. Все пять выдач материалов — списки сайта и админки, поиск и обе карточки — содержат вложенный объект:

```json
{
  "thickness": {
    "id": 1,
    "name": "Тонкая плита",
    "value": 4.1
  }
}
```

Плоские `depth` и `thicknessId` из ответов материалов удалены по уточнению пользователя. Потребителям нужно читать `thickness.id`, `thickness.name` и `thickness.value`. Имена JSON совпадают с C#-свойствами с учётом camelCase; атрибутов переименования нет.

`GET /api/materials/search` и `/api/materials/filters` принимают `thicknessIds`; несколько значений передаются повторением: `?thicknessIds=1&thicknessIds=2`. Внутри группы действует ИЛИ, между группами — И. Без параметра ограничения нет. Неизвестные и неположительные ID, более 100 значений отклоняются.

Полные списки `/api/materials` и `/api/admin/materials` не принимают query-параметры и возвращают только `items`. Справочник толщин доступен отдельно через `/api/materials/thicknesses`. `/api/materials/filters` возвращает `thicknesses: [{ id, name, value, count }]`: учитываются остальные ограничения, собственный выбор толщины исключается из расчёта, выбранные толщины с нулевым количеством сохраняются.

Числовой фильтр `depths` и фасет `depths` сохранены для совместимости публичного поиска. При совместном выборе `depths` и `thicknessIds` применяется пересечение; в счётчиках толщины исключаются оба ограничения. Это параметры поиска, а не плоские поля материала в ответе.

## Миграции через EF Core

Созданы инструментом EF Core:

1. `20260929195039_AddMaterialThicknesses`: справочник с названием и уникальным индексом, временно nullable-ссылка в материалах. В конце `Up` согласованный `migrationBuilder.Sql` переносит все фактические уникальные `depth`, формирует названия (`4,1 мм`, `16 мм` и т. д.) и заполняет ссылки. Значения и ID не зашиты в код.
2. `20260929195106_RequireMaterialThickness`: обязательная ссылка и удаление старого `depth`. В `Down` после восстановления столбца значения возвращаются из справочника, поэтому откат обеих миграций сохраняет толщины.

Обе миграции пользователь применяет штатной командой из корня репозитория:

```sh
dotnet ef database update --project catalog-api/Catalog.Database
```

Отдельных SQL-файлов для запуска нет. Перед обновлением остановите запись старой версией API; новую запускайте после успешного применения обеих миграций. Целевой контур выбирается штатной настройкой проекта/подключения. Агент миграции не выполнял. Старые неприменённые версии трёх миграций удалены через `dotnet ef migrations remove`; окончательные миграции созданы заново через `dotnet ef migrations add`.

## Проверка после применения

Проверить сохранение количества материалов и распределения толщин; создание дробной толщины с названием; изменение только имени; запрет дубля и удаления используемой толщины; создание/обновление материала со ссылкой; вложенный объект в пяти выдачах; один и несколько ID совместно с calculators, categoryIds и inStock; счётчики фасетов и выбранный ID с нулевым количеством. Изменения выполнять тестером, созданные данные удалять.

Актуальные выполненные проверки и ограничения записаны в TEST_EXECUTION.md. Полный разбор правил и терминов — в MATERIAL_THICKNESSES_AGENTS_AUDIT.md.
