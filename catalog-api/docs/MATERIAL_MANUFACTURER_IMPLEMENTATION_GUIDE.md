# MaterialManufacturer: принятые решения

Документ фиксирует итоговое устройство справочника производителей материалов.

## Модель данных

Техническая сущность `MaterialManufacturer` хранится в таблице `catalog.material_manufacturers` и содержит:

- `Id` — идентификатор;
- `Name` — обязательное название длиной не более 100 символов;
- `OrderByCol` — порядок отображения;
- коллекцию связанных материалов.

Материал содержит обязательный внешний ключ `MaterialManufacturerId` и навигационное свойство `MaterialManufacturer`. В базе используется колонка `material_manufacturer_id`.

Удаление производителя, который используется материалами, запрещено. Для внешнего ключа используется `DeleteBehavior.Restrict`, а API предварительно возвращает понятную бизнес-ошибку.

Технический префикс `Material` отличает этот справочник от будущих производителей плёнок, красок и других сущностей. Во внешний JSON-контракт префикс не выносится.

## API

Базовый маршрут:

```text
/api/materials/manufacturers
```

Методы:

- `GET /api/materials/manufacturers` — публичный список;
- `GET /api/materials/manufacturers/{id}` — публичная карточка;
- `POST /api/materials/manufacturers` — создание;
- `PUT /api/materials/manufacturers/{id}` — редактирование;
- `DELETE /api/materials/manufacturers/{id}` — удаление;
- `POST /api/materials/manufacturers/change-order-col` — перемещение вверх или вниз.

GET-методы доступны анонимно. Изменяющие методы требуют cookie-аутентификацию. Контроллер использует `OpenApiTagOrder(4)` и полный набор принятых в проекте OpenAPI-атрибутов.

## DTO и наименование

В самостоятельном API используется `ManufacturerDto`:

```json
{
  "id": 1,
  "name": "Увадрев",
  "orderByCol": 1
}
```

В публичных и административных контрактах материала производитель возвращается единым вложенным объектом без `orderByCol`:

```json
{
  "manufacturer": {
    "id": 1,
    "name": "Увадрев"
  }
}
```

Модели создания и редактирования материала принимают обязательное поле `manufacturerId`. Имена `manufacturer`, `manufacturerId` и `ManufacturerDto` намеренно не содержат повторного слова `Material`.

## Создание и редактирование

Модель принимает:

```json
{
  "name": "Увадрев"
}
```

FluentValidation проверяет обязательность, максимальную длину и уникальность названия. При редактировании текущая запись исключается из проверки уникальности. Отдельного уникального индекса по `Name` в базе нет.

Название перед сохранением обрезается по краям. Новая запись получает `OrderByCol = max(OrderByCol) + 1`.

## Сортировка

Список сортируется по `OrderByCol`, на колонку установлен уникальный индекс. Команда изменения порядка принимает `id` и строковое направление `UP` либо `DOWN`.

Запись обменивается значением `OrderByCol` с соседней записью. Перемещение первого элемента вверх и последнего элемента вниз возвращает `400 Bad Request`. Обмен выполняется в транзакции через временное уникальное значение.

## Начальные данные

Справочник содержит десять производителей:

1. Увадрев;
2. Swiss Krono;
3. Ultradecor;
4. Egger;
5. Lamarty;
6. AGT;
7. Evogloss;
8. Nordeco;
9. Byspan;
10. Прочее.

Существующие материалы распределены по производителям на основании названий категорий и материалов. Нераспознанные позиции отнесены к «Прочее», после чего внешний ключ сделан обязательным.

## Миграции

- `AddManufacturers` — первоначально создаёт справочник и nullable-связь для безопасного развёртывания;
- `SeedManufacturersAndRequireManufacturer` — заполняет справочник, назначает производителей существующим материалам и устанавливает `NOT NULL`;
- `RenameManufacturersToMaterialManufacturers` — без потери данных переименовывает техническую таблицу, внешний ключ, индексы и ограничения.

Эти миграции являются частью зафиксированной истории схемы.
