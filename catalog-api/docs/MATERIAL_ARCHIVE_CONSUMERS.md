# Потребители архивных материалов

Архив хранится отдельно от действующих материалов. При переносе сохраняются Id материала и существующие записи изображений, связей с кромками и маркировок. У изображения и связи изменяется только владелец: MaterialId либо ArchivedMaterialId.

Сайт, список материалов для Calculate и список выбора в ЛК читают только действующие материалы. Чтобы существующие расчёты и заявки продолжали открываться, чтение материала по Id для Calculate и ЛК, чтение материалов по списку Id и подбор цены кромки ищут данные также в архиве. Публичное получение изображения по GUID использует общую таблицу изображений. Синхронизация со Стройдвором доступна только для действующих материалов.

Административные списки связей читают одну общую таблицу и включают архивные отношения. В контракте materialId остаётся прежним положительным Id материала: для архивной записи он сохраняется в вычисляемом OwnerMaterialId. Изменение кромок и маркировок по прежнему Id работает с существующей связью независимо от владельца.

Владелец связи определяется вычисляемым сохранённым OwnerMaterialId = COALESCE(MaterialId, ArchivedMaterialId). Первичный ключ связи и строки маркировки — собственный Id. Дополнительный ключ связи — OwnerMaterialId и EdgeId. Маркировки используют прежние MaterialId и EdgeId для ссылки на связь и сохраняют MarkingId; при переносе их строки не меняются, поскольку Id материала сохраняется. Массовое изменение связей кромки может включать действующие и архивные материалы в одном запросе. Все изменения такого запроса выполняются одной Serializable-транзакцией с существующим повтором конфликтов; ручной SQL для блокировок не используется.

Использование материалов в справочниках учитывает оба хранилища. Использование кромок и маркировок учитывается по общим таблицам связей. Удаление категории, типа, производителя, формата, толщины, кромки или маркировки запрещено, пока их использует хотя бы один материал в архиве. Внешние ключи дополнительно защищают эти связи от конкурентного удаления.
