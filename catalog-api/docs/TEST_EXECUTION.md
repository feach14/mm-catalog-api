# Результат последней проверки

Дата: 01.11.2026.

Проверена динамическая отмена трансформации артикула после удаления старых связей кромки в каталоге и чтение изменённого старого значения без кеша.

## Контур и воспроизводимость

Проверка выполнялась напрямую через реальные `DeleteEdgeArticleReplacementsCommandHandler` и `GetEdgeArticleFor1CQueryHandler` с Microsoft EF Core InMemory. Для истории использовалась локальная заглушка `ICatalogHistoryWriter`. Все артикулы фикстуры вымышленные. Рабочие БД, HTTP, cookie и уведомления не использовались; сервер и порт не запускались.

Воспроизводимый console harness сохранён в `/Users/mmcore/Documents/ChatGPT/Век/raskroy-edge-article-dynamic-checks`. Команда из этой папки:

```sh
dotnet run --project CatalogEdgeArticleDynamicChecks.csproj --no-restore -p:UseSharedCompilation=false -m:1
```

Подготовка зависимостей из локального NuGet cache и полный порядок запуска описаны в `README.md` этой папки. Результат последнего запуска сохранён рядом в `verification.json`.

## Результаты

Успешно выполнены 14 проверок:

- Контекст действительно использует только Microsoft EF InMemory.
- При наличии нескольких старых связей возвращается явно выбранный старый артикул полностью как сохранён.
- Изменение выбранного старого значения через другой EF context учитывается при следующем вызове тем же и новым query handler; исходные пробелы сохраняются.
- Реальный handler удаления удаляет все старые связи выбранной кромки и сохраняет результат.
- После удаления та же и новая query-операция возвращают текущий артикул без трансформации, хотя согласованный `id` остаётся в конфигурации.
- Отдельно проверено удаление единственной старой связи: тот же handler/context и новый handler возвращают текущий артикул; оставшаяся конфигурация не мешает.
- Оба удаления записывают историю только в локальную заглушку.

Production C# не менялся: существующий query читает актуальные связи при каждом вызове, а отсутствие истории проверяет до конфигурации. Обновлены только стабильные сценарии и описание поведения после удаления через фронт каталога. Повторная обязательная проверка форматирования production C# для этого прогона не требовалась. Полный регрессионный прогон не выполнялся.

Сборка и выполнение console harness успешны. Данные EF InMemory завершили жизненный цикл вместе с процессом; сгенерированные `bin` и `obj` удалены, исходники и результат проверки сохранены.
