# Результат целевой проверки подбора кромки 1/0,8 мм

- `dotnet build catalog-api/catalog-api.slnx --no-restore`: успешно, 0 ошибок и предупреждений.
- `dotnet format catalog-api/catalog-api.slnx --verify-no-changes --no-restore`: успешно.
- `git diff --check`: успешно; изменённые файлы — UTF-8 без BOM, окончания строк LF.
- Catalog API запущен с актуальной сборкой на стандартном локальном порту 5005 в Development; данные и Data Protection используют только `mm-debug`.
- Вызов реального handler через EF Core и PostgreSQL: успешно 10 целевых сценариев. Запрос 1 мм выбирает единственную связанную кромку 0,8 либо 1 мм с маркировкой «Век ЛК» и без ограничения маркировки. Проверены фактические цена, артикул, название, кратность и тип продажи.
- Маркировка продолжает ограничивать подбор; прямой запрос 0,8 мм сопоставляется точно, запрос 0,4 мм не выбирает 0,8 мм. Две подходящие связи 1/0,8 мм возвращают прежнюю ошибку неоднозначности в обоих режимах.
- Созданы только собственные временные материал, кромки, размеры и связи внутри транзакции. Транзакция отменена; отсутствие созданных записей после отката проверено.
- HTTP-проверки актуального сервиса: `GET /api/for-calculate/edges/price` для материала #134 и отсутствующей толщины `12345.678` с `forVek=true` и `forVek=false` возвращает `400 ProblemDetails` с прежним текстом. Маркировка упоминается только для ВЕК; ID и название материала в ответ не добавляются.
- В Error-логах обоих запросов подтверждены ID и название материала, запрошенная толщина и требуемая маркировка либо отсутствие ограничения по ней.
- Полный регресс не запускался.
