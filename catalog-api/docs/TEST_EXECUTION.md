# Результат последней целевой проверки

Дата: 12.11.2026. Область: тип продажи и кратность покупной кромки для Calculate API. Полный регресс не выполнялся.

## Окружение

Catalog API — `https://catalog-api.debug.feach.ru:5005`, актуальная сборка. Основное подключение и Data Protection используют только `mm-debug`. Постоянные настройки не менялись. Проверенные endpoints доступны анонимно; авторизация не требовалась.

## Результаты

- Сборка `dotnet build catalog-api/catalog-api.slnx --no-restore`: успешно, 0 ошибок и предупреждений.
- Проверка `dotnet format catalog-api/catalog-api.slnx --verify-no-changes --no-restore`: успешно.
- `EDGE-CALC-01`: OpenAPI содержит обязательные `price`, `article`, `quantityMultiple`, `saleUnitType` с русскими описаниями. Кратность имеет стандартную для проекта decimal-схему; enum содержит строковые `Meter` и `Roll`. Описание цены различает метр и бухту.
- OpenAPI `EdgeSaleUnitFilterItemDto` содержит обязательные `id`, `name`, `saleUnitType`; поле позволяет административному фронтенду выбрать единицу цены.
- `EDGE-CALC-02`, `EDGE-CALC-03`: read-only EF-проверка и живые HTTP-ответы для существующей однозначной связи материала 42, толщины 0.4 мм и единицы `Meter` совпали по цене, артикулу, длине 1 м и типу продажи. Проверены обе ветки `forVek=false` и `forVek=true`.
- Запрос с `materialId=0` и `thickness=0` возвращает `400`.

## Данные и ограничения

Записей в БД и новых тестовых сущностей не создавалось. Цены не пересчитывались. В `mm-debug` не найдено существующей однозначной связи с типом `Roll` для обеих веток отбора, поэтому живое чтение бухты не проверено. Контракт для `Roll` проверен через OpenAPI; расчёт стоимости бухт проверяется в Calculate API. Временный скрипт проверки удалён, основной dev-сервис оставлен включённым.
