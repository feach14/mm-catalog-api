# Последний целевой прогон

Дата: 2026-10-08. Область: пакетное чтение материалов по Id для Calculate API. Полный регресс не выполнялся.

## Результат

- Сборка Catalog API: 0 ошибок, 0 предупреждений. Полная проверка `dotnet format catalog-api/catalog-api.slnx --verify-no-changes --no-restore` прошла; изменённые файлы соответствуют UTF-8 без BOM, LF и отсутствию завершающего LF.
- Пройдено 20 изолированных HTTP-проверок через Microsoft TestServer и EF Core InMemory. Использованы реальные контроллер, handler, FluentValidation, OpenAPI и обработка ошибок.
- `POST /api/for-calculate/materials/by-ids` возвращает только запрошенные материалы из разных категорий, включая скрытые материалы и категории. Подтверждены текущая категория в DTO и сортировка по категории и материалу.
- Неизвестные Id пропускаются; список только из неизвестных Id возвращает `200` и `items: []`. Отсутствующее поле, null, пустой список, нулевые/отрицательные Id и повторы отклоняются с `400`.
- Без сессии возвращается `401`, обычному пользователю — `403`, тестовой роли tester — `200`. Прежний GET материалов по-прежнему требует `categoryId`.
- Сгенерированный `/swagger/v1/swagger.json` проверен на новый POST-маршрут, summary `MaterialsByIds`, обязательность body, описания и required-поля схем запроса и результата.
- Стабильные сценарии: `CALC-07—CALC-10` в [TEST_CASES.md](TEST_CASES.md).
- Вместе с 31 проверкой Calculate пройдена 51 изолированная HTTP-проверка, ошибок нет.

## Контур и очистка

TestServer работал в памяти без сетевых портов. EF Core InMemory использовал только временные тестовые материалы и категории. Текущие API пользователя не запускались, не останавливались и не перезапускались; подключения к реальным БД, Accounts API и Seq не выполнялись. Реальная авторизация и cookie не использовались. БД и их схемы не изменялись, миграции не создавались и не применялись.

Временные приложения завершены, проекты проверок удалены. Core и настройки текущих процессов не изменялись в рамках этой проверки.

## Границы проверки

Проверка не подтверждает работу нового endpoint в текущем процессе пользователя или выполнение запросов на PostgreSQL. Для появления новых endpoint требуется перезапустить оба API: Catalog и Calculate.
