# Результат целевой проверки SearchText без категории

Дата: 19 ноября 2026 года. Проверена локальная сборка Catalog API на `https://debug.feach.ru:5005`, данные и ключи Data Protection — только `mm-debug`.

## Изменение и пересборка данных

- Категория исключена из формирования `SearchText`, загрузки справочников в helper и пересчёта при изменении категории.
- API один раз запущен с `--MaterialSearch:Rebuild=true`: пересобраны 1062 материала партиями по 500. Новые миграции не создавались и не применялись.
- Проверка через EF Core подтвердила: все 1062 сохранённых поисковых текста соответствуют текущему helper; пустых и устаревших значений — 0.
- После пересборки API перезапущен без параметра; локальный сервис оставлен включённым. Запрос по артикулу `9712` возвращает материал «Айрон Рок U9712 LF», Id 134.

## Целевые HTTP-проверки

Через временный импорт существующего `http_regression_runner.py` вызвана функция `run_material_search_scenarios`. Самостоятельная команда `--material-search` и полный регресс не запускались.

Исторический тестер недоступен; использован отдельный тестовый менеджер `mm-debug` согласно правилам тестовых учётных записей. Проверки роли тестера в этот прогон не входят.

| Сценарий | Результат |
|---|---|
| `SEARCH-02` | Символы `%`, `_` и `\` ищутся буквально |
| `SEARCH-09` | Поиск по названию, типу, артикулу и производителю работает в любом порядке; уникальное название категории не даёт совпадений |
| `SEARCH-10` | Разделители размеров, десятичная запятая/точка и единицы измерения обрабатываются одинаково |
| `SEARCH-11` | Числовые границы размеров соблюдаются; поиск по цифровой части артикула сохранён |
| `SEARCH-12` | Обновление материала и его производителя сразу отражается в поиске |
| `SEARCH-13` | Изменение типа, производителя, формата и толщины обновляет поиск; старое и новое имена категории не дают совпадений после её переименования |
| `SEARCH-14` | Клонирование, архивирование и восстановление сохраняют корректный поисковый текст |
| `SEARCH-15` | Видимость материала, категории и типа соблюдается; выдача, `totalCount` и все счётчики фасет согласованы |

Все 8 сценариев пройдены. Подтверждённых дефектов нет.

- `dotnet build catalog-api/catalog-api.slnx --no-restore` — успешно, предупреждений и ошибок нет.
- `dotnet format catalog-api/catalog-api.slnx --verify-no-changes --no-restore` — успешно.
- Синтаксис Python, `git diff --check`, UTF-8 без BOM и LF отслеживаемых текстовых файлов проверены.
- Префикс собственных данных: `codex-search-85d587c1835e`. Все созданные материалы и справочники удалены; оставшихся сущностей — 0.
- Через EF Core удалены 38 записей истории только этого прогона; оставшихся записей по его префиксу — 0.
- Фронтенды не менялись: оба используют обновлённый публичный поиск Catalog API. В этом прогоне интерфейсы браузера отдельно не проверялись.
