# Результат целевой проверки упрощения обработчиков

Дата: 26 ноября 2026 года. Полный регресс не выполнялся.

- Удалены 20 вложенных зависимостей: чтение процентов материалов и кромок,
  переход компактных списков к полным и пять архивных веток материалов.
  Синхронизация со Стройдвором сохраняет общую пакетную обработку.
- Настройки читаются напрямую через EF Core один раз на операцию;
  общие объекты расчёта цен не выполняют I/O и не зависят от DI.
- 144 проверки на собранной DLL без БД и HTTP — успешно: три цены и проценты,
  полнота 12 ключей настроек, ручная и поставщицкая база, нули,
  соответствие 0,8 → 1 мм и неподдерживаемые толщины.
- Обе компактные EF-проекции переведены в SQL через Npgsql без подключения
  к БД; сохранены сортировка, комментарии и выбор миниатюры 240 → 480.
- Архивные ветки проверены сравнением с прежним кодом: транзакции,
  история, изображения, поиск и отмена операций сохранены.
- `dotnet build --no-restore` — успешно, без ошибок и предупреждений;
  `dotnet format --verify-no-changes --no-restore` — успешно.
- Проверены кодировки UTF-8 без BOM, окончания LF, отсутствие финального LF
  и `git diff --check`.
- Чтение истории EF подтвердило: в `mm-debug` ещё ожидают применения
  `20261126125122_AddPricePercentages` и `20261126125227_RemovePricePercentages`.
  Миграции и данные не изменялись. Новый API не перезапускался: его чтения
  требуют ещё не созданную таблицу `catalog.price_percentages`.
  HTTP-проверка новых цен и сохранения настроек в IAB ожидает миграций.
