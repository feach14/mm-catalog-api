# Артикулы кромок для JSON раскроя

Временный контракт для выгрузки расчётов ЛК в 1С:

```http
GET /api/for-vek-lk/edges/article-for-1c?article=003-25-PE-KR-0.4-19
```

Ответ `200 OK`:

```json
{ "article": "003-25-PE-KR-0,4-19" }
```

Endpoint доступен анонимно: JSON раскроя также выдаётся через существующую интеграцию 1С без пользовательской cookie. Операция возвращает только один артикул и не изменяет данные.

По точному текущему артикулу ищутся записи существующей таблицы `edge_article_replacements`, доступные в разделе «Старые артикулы кромок». При нескольких карточках с одинаковым текущим артикулом рассматриваются соответствия всех этих карточек. Старые значения не нормализуются и не обрезаются.

Правила применяются в следующем порядке:

1. Если замены нет, включая неизвестный и уже старый артикул, возвращается исходный `article` без изменений.
2. Единственный старый артикул возвращается полностью как хранится, включая запятые и пробелы. Конфигурация на эту ветку не влияет.
3. При нескольких старых артикулах сначала применяется явно согласованный выбор из `EdgeArticleFor1CSelections`: ключ — текущий артикул, значение — `id` старого артикула. Выбранная запись должна принадлежать текущему артикулу. Значение возвращается без изменений, в том числе с согласованными пробелами. Отсутствующий или принадлежащий другой кромке настроенный `id` возвращает `400 ProblemDetails` с кандидатами; автоматический выбор не маскирует ошибку конфигурации.
4. Если согласованный выбор отсутствует, возвращается единственный вариант без пробельных символов в любой позиции.
5. Если все варианты содержат пробельные символы, возвращается первый добавленный — запись с наименьшим `id`, полностью как хранится.
6. Несколько вариантов без пробелов без согласованного выбора возвращают `400 ProblemDetails` с кандидатами.

В профиле Vek пользователь согласовал десять замен:

| Текущий артикул | Id старого артикула |
|---|---|
| `K097-343-0.4-19` | 304 |
| `K097-343-2.0/19` | 307 |
| `9708-1.0/19` | 338 |
| `0164-280-PE-2.0/19` | 326 |
| `31104-316-SE-2.0/19` | 329 |
| `3175-0143-SE-2.0/19mm` | 331 |
| `424-SE-2.0/19` | 333 |
| `7045-261-29-PE-2.0/19` | 334 |
| `174-18-SM-1.0/19` | 35 |
| `3129-094-SE-UD 2.0/19` | 226 |

Для K097 выбрана латинская `K`, для 9708 — толщина `1,0`. Для 174 и 3129 выбраны варианты с правильной толщиной с сохранением исходных пробелов; они имеют приоритет перед вариантами без пробелов с ошибочной толщиной. Исходные старые значения в таблице не меняются.

Пустой, состоящий из пробелов или превышающий 100 символов вход также возвращает `400`.

Операция только читает каталог. Схема БД и существующие соответствия не меняются; миграция не требуется. Артикулы расчёта заменяются потребителем при формировании JSON, без перезаписи сохранённого расчёта и цен.

Каждый вызов читает актуальные связи из БД; результат преобразования не кешируется в handler. Если в разделе «Старые артикулы кромок» удалить связи кромки, следующий JSON раскроя возвращает текущий артикул без трансформации. Удаление в этом разделе выполняется по `edgeId` и удаляет все старые артикулы выбранной кромки. Оставшаяся запись `EdgeArticleFor1CSelections` не препятствует этому: отсутствие связей проверяется раньше конфигурации. Изменение старого значения также учитывается при следующем вызове, с сохранением нового значения полностью как хранится.
