# Тест-кейсы Catalog API

## Контекст

- Авторизация менеджера: Accounts API, `POST /api/sign/in`.
- Публичные чтения: материалы, категории, карточки и изображения.
- Авторизация cookie требуется для чтений административной панели и всех изменений данных.
- Все enum в JSON передаются и возвращаются строковыми именами, а не числами: например, `"direction": "UP"` и `"countTypeEnum": "M2"`.
- Проверки выполняются только через HTTP API. Состояние считается корректным по кодам ответа и данным, доступным через endpoints.
- Удалённый материал намеренно остаётся доступен через `GET /api/materials/{id}` и `GET /api/materials/admin/{id}` для клиента, которому известен его id. Это ожидаемое поведение, а не дефект.

## Автоматизированный HTTP-прогон

- Полный набор сценариев можно запускать командой `python3 catalog-api/http_regression_runner.py` из корня репозитория.
- Раннер работает только через HTTP-интерфейсы Accounts API и Catalog API, самостоятельно запускает и перезапускает локальный Catalog API и удаляет созданные тестовые сущности.
- Раннер хранится в репозитории как рабочая история и вспомогательный инструмент. ИИ-агентам разрешено без дополнительных согласований исправлять, расширять и актуализировать его вместе с изменениями тест-кейсов и API.
- Перед запуском должны быть собраны проекты и запущен локальный Accounts API на порту `5003`; Catalog API на порту `5005` должен быть свободен.

## PREP — подготовка

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| PREP-01 | Получить cookie менеджера | Авторизоваться через Accounts API | Успешный ответ, клиент получил `AccountsApiCookie` |
| PREP-02 | Подготовить авторизованный клиент | Открыть Scalar Catalog API в том же профиле либо использовать HTTP-клиент с cookie | Cookie отправляется в закрытые запросы |
| PREP-03 | Подготовить неавторизованный клиент | Использовать инкогнито-окно либо клиент без cookie | Запросы выполняются без cookie |

## AUTH — доступ

| ID | Сценарий | Запрос | Ожидаемый результат |
|---|---|---|---|
| AUTH-01 | Публичный список материалов | `GET /api/materials` без cookie | `200 OK` |
| AUTH-02 | Публичный список категорий | `GET /api/materials/categories` без cookie | `200 OK` |
| AUTH-03 | Публичная карточка материала | `GET /api/materials/{id}` без cookie | `200 OK` для существующего id |
| AUTH-04 | Публичная карточка категории | `GET /api/materials/categories/{id}` без cookie | `200 OK` для существующего id |
| AUTH-05 | Публичное изображение | `GET /api/materials/images/{fileGuid}` без cookie | `200 OK` для существующего файла |
| AUTH-06 | Изменения без авторизации | `POST`, `PUT`, `DELETE`, сортировка без cookie | `401 Unauthorized` |
| AUTH-07 | Список административной панели без авторизации | `GET /api/materials/admin` без cookie | `401 Unauthorized` |
| AUTH-08 | Закрытый метод с cookie | Выполнить разрешённый закрытый запрос | Успешный ответ |

## CAT — CRUD категорий

Перед сортировкой создать три уникальные тестовые категории.

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| CAT-01 | Создание категорий | Трижды вызвать `POST /api/materials/categories` | Все запросы успешны, получены id |
| CAT-02 | Список категорий | Вызвать `GET /api/materials/categories` | Созданные категории есть в списке, порядок соответствует `OrderByCol` |
| CAT-03 | Карточки категорий | Запросить каждую категорию по id | Данные соответствуют созданным |
| CAT-04 | Обновление категории | Изменить среднюю категорию через `PUT` | Изменения видны в повторном `GET` |
| CAT-05 | Сортировка вверх | Поднять среднюю категорию | Она меняется местами с предыдущей |
| CAT-06 | Сортировка вниз | Опустить категорию | Она меняется местами со следующей |
| CAT-07 | Верхняя граница сортировки | Поднять первую категорию | Бизнесовая ошибка |
| CAT-08 | Нижняя граница сортировки | Опустить последнюю категорию | Бизнесовая ошибка |
| CAT-09 | Удаление используемой категории | Создать материал в категории и удалить категорию | Удаление отклонено; категория и материал сохранены |
| CAT-10 | Удаление свободной категории | Удалить материал, затем категорию | Категория удалена и отсутствует в списке |

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| MAT-01 | Создание материалов | Создать минимум три материала | Успех, получены id |

| MAT-03 | Фильтры | Проверить `raskroy`, `pvhFacades`, `emalFacades` | Возвращаются только применимые материалы |
| MAT-04 | Обновление | Изменить поля через `PUT /api/materials/{id}` | Изменены свойства, категория, флаги, цена и единица измерения |
| MAT-05 | Проверка обновления | Повторить публичный `GET` и `GET` административной панели | Отображаются новые значения |
| MAT-06 | Сортировка внутри категории | Изменить порядок материалов первой категории | Меняется порядок только этой категории |
| MAT-07 | Изоляция сортировки | Проверить вторую категорию | Её порядок не изменился |

## IMG — загрузка изображений

Все загруженные в ходе прогона изображения должны быть последовательно использованы в сценариях создания и обновления тестового материала. Проверяется только наблюдаемое поведение HTTP API. После завершения сценариев ни один тестовый GUID не должен возвращать изображение через API.

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| IMG-01 | Доступ к загрузке | Отправить `POST /api/materials/images` без cookie | `401 Unauthorized` |
| IMG-02 | Допустимые форматы | Загрузить PNG, JPEG и WebP через multipart-поле `file` | Для каждого файла `200 OK`; возвращены GUID и корректный `contentType` |
| IMG-03 | Валидация загрузки | Отправить пустой, слишком большой или неподдерживаемый файл | `400 Bad Request` с понятной ошибкой |
| IMG-04 | Доступность загруженных файлов | Запросить PNG, JPEG и WebP через `GET /api/materials/images/{fileGuid}` до привязки к материалу | Для каждого GUID получен `200 OK`, корректный `Content-Type`, байты совпадают с исходным файлом |
| IMG-05 | Загруженный файл переживает перезапуск | Перезапустить API и вызвать `GET /api/materials/images/{fileGuid}` для PNG из `IMG-02` | `200 OK`, корректный `Content-Type`, файл совпадает с исходным |
| IMG-06 | Создание материала после перезапуска | После перезапуска передать GUID PNG из `IMG-02` при создании материала | Материал создан; GUID PNG указан в карточке материала |
| IMG-07 | Привязка изображения при создании | Создать материал с GUID PNG и запросить карточку материала и изображение через публичные endpoints | В карточке указан GUID PNG; изображение возвращается с исходными MIME-типом и байтами |
| IMG-08 | Привязка изображения при обновлении | Передать GUID JPEG из `IMG-02` в `PUT /api/materials/{id}`, затем запросить карточку материала, PNG и JPEG | В карточке указан GUID JPEG; JPEG возвращается с исходными байтами; прежний GUID PNG возвращает ошибку «Файл не найден» |
| IMG-09 | Повторное получение изображения | Дважды подряд запросить актуальное изображение | Оба запроса возвращают `200 OK`, одинаковый `Content-Type` и одинаковые байты |
| IMG-10 | Получение изображения позднее | Повторить запрос актуального изображения позднее, не перезапуская API и не изменяя материал | Изображение по-прежнему возвращается с исходными MIME-типом и байтами |
| IMG-11 | Замена изображения | Заменить JPEG на WebP из `IMG-02` через `PUT`, затем запросить карточку материала и оба GUID | В карточке указан GUID WebP; JPEG возвращает ошибку «Файл не найден»; WebP возвращается с исходными MIME-типом и байтами |
| IMG-12 | Изображение после перезапуска | Перезапустить API и дважды запросить актуальный WebP | Оба запроса возвращают `200 OK`, корректный `Content-Type` и исходные байты |
| IMG-13 | Удаление изображения вместе с материалом | Запросить актуальный WebP, удалить материал и повторить запрос WebP | До удаления получен `200 OK`; после удаления GUID возвращает ошибку «Файл не найден» |
| IMG-14 | Итоговая проверка GUID | После удаления тестового материала запросить все GUID, полученные в `IMG-02` | Каждый запрос изображения возвращает ошибку «Файл не найден» |

## VAL — валидация

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| VAL-01 | Пустые обязательные поля | `400 Bad Request` с понятной ошибкой |
| VAL-02 | Нулевая или несуществующая категория | `400 Bad Request` |
| VAL-03 | Нулевые/отрицательные размеры, площадь, периметр, толщина | `400 Bad Request` |
| VAL-04 | Цена `<= 0` при количестве больше нуля | `400 Bad Request` |
| VAL-05 | Не включён ни один калькулятор | `400 Bad Request` |
| VAL-06 | Дублирующееся название материала | `400 Bad Request` |
| VAL-07 | Несуществующий id материала или категории | Корректная ошибка API |
| VAL-08 | Недопустимое направление сортировки | Корректная ошибка API |
| VAL-09 | Несуществующий GUID изображения | Корректная ошибка API |

## FIN — завершение

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| FIN-01 | Удалить тестовые материалы | Тестовые материалы удалены; связанные GUID изображений недоступны через публичный endpoint |
| FIN-02 | Удалить тестовые категории | Тестовые категории удалены |
| FIN-03 | Контрольная выдача и изображения | Тестовые записи отсутствуют в публичных списках и выдаче административной панели; запросы всех тестовых GUID возвращают ошибку «Файл не найден» |
