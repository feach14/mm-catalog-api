# Тест-кейсы Catalog API

## Контекст

- Авторизация выполняется через Accounts API. Учётные данные и правила выбора пользователя находятся в `mm-accounts-api/accounts-api/docs/TEST_CREDENTIALS.md`.
- Все основные функциональные сценарии и очистка тестовых данных выполняются только тестером. Cookie менеджера или администратора не может быть cookie по умолчанию; она используется только в ролевых проверках и изолированных `HIST-01—HIST-12`.
- Изолированные сценарии истории используют отдельный уникальный префикс. После основного прогона по его префиксу не должно быть ни одной записи истории; события `HIST-01—HIST-12` проверяются только по своему префиксу.
- Публичные чтения: материалы, карточки и изображения.
- Авторизация cookie требуется для чтений административной панели и всех изменений данных.
- Все enum в JSON передаются и возвращаются строковыми именами, а не числами: например, `"direction": "UP"` и `"countTypeEnum": "M2"`.
- Проверки выполняются только через HTTP API. Состояние считается корректным по кодам ответа и данным, доступным через endpoints.
- После физического удаления материал недоступен через публичную и административную карточки.

Проверки выполняются перед функциональным HTTP-прогоном. Требования корневого `.editorconfig` распространяются на все отслеживаемые текстовые файлы основного репозитория и submodule `core`.

| ID | Сценарий | Шаги | Ожидаемый результат |

| CODE-02 | Кодировка и окончания строк | Проверить все отслеживаемые текстовые файлы основного репозитория и `core` | Все файлы являются валидным UTF-8 без BOM, используют LF и не содержат CR/CRLF |

## Фиксация результата прогона

- `catalog-api/docs/TEST_EXECUTION.md` содержит только результат последнего прогона.
- При новом прогоне предыдущий отчёт полностью заменяется; история прогонов в файле не ведётся.
- В отчёте указываются среда, инструмент, результаты групп сценариев, связанные дефекты и результат очистки тестовых данных.

## Автоматизированный HTTP-прогон

- Автоматизированная часть сценариев запускается командой `python3 catalog-api/http_regression_runner.py` из корня репозитория.
- Раннер работает только через HTTP-интерфейсы Accounts API и Catalog API, самостоятельно запускает и перезапускает локальный Catalog API и удаляет созданные тестовые сущности.
- Раннер обязан установить cookie тестера как cookie по умолчанию до создания любых тестовых сущностей. Отдельные ролевые проверки используют cookie обычного пользователя, тестера, менеджера и администратора; изолированные проверки создания истории используют менеджера или администратора и отдельный префикс.
- Для `HIST-01—HIST-12` раннер создаёт отдельный положительный целочисленный `runId` и включает маркер `codex-history-{runId}` во все названия тестовых сущностей. После всех проверок раннер вызывает от имени тестера `DELETE /api/admin/catalog/history/test-runs/{runId}`, проверяет число удалённых записей и нулевую выдачу по маркеру прогона.
- Глобальный `totalCount` истории не сравнивается: параллельные реальные изменения каталога не должны приводить к ложному провалу тестов.
- Раннер хранится в репозитории как рабочая история и вспомогательный инструмент. ИИ-агентам разрешено без дополнительных согласований исправлять, расширять и актуализировать его вместе с изменениями тест-кейсов и API.
- Перед запуском должны быть собраны проекты и запущен локальный Accounts API на порту `5003` (либо по адресу из `ACCOUNTS_API_URL`) на том же контуре базы данных и Data Protection, что и Catalog API; Catalog API на порту `5005` должен быть свободен.
- Перед стартом раннер обязан проверить порт Catalog API, выбранный для прогона (по умолчанию `5005`). Если порт занят, прогон немедленно прекращается до запуска Catalog API и создания тестовых данных. Агент не должен останавливать существующий процесс, выполнять тесты через уже запущенный API или самостоятельно выбирать другой порт/endpoint. Продолжить на другом порту можно только после прямого указания пользователя с конкретным портом или `CATALOG_API_URL`.

## AUTH — доступ

Публичное чтение материалов и изображений использует `/api/materials/...`. Категории доступны через административные endpoints и защищённый контракт `/api/calculate/material-categories`. Административные списки и карточки, создание, изменение, удаление, сортировка и загрузка изображений используют `/api/admin/materials/...` и требуют cookie пользователя с ролью `manager`, `admin` или `tester`.

| ID | Сценарий | Запрос | Ожидаемый результат |
|---|---|---|---|
| AUTH-01 | Публичный список материалов | `GET /api/materials` без cookie | `200 OK` |
| AUTH-02 | Удалённый публичный список категорий | `GET /api/materials/categories` без cookie | `404 Not Found` |
| AUTH-03 | Публичная карточка материала | `GET /api/materials/{id}` без cookie | `200 OK` для существующего id |
| AUTH-04 | Административная карточка категории | `GET /api/admin/materials/categories/{id}` с cookie тестера | `200 OK` для существующего id |
| AUTH-05 | Публичное изображение | `GET /api/materials/images/{fileGuid}` без cookie | `200 OK` для существующего файла |
| AUTH-05A | Административные размеры плит | `GET /api/admin/materials/sheet-sizes` и `GET /api/admin/materials/sheet-sizes/{id}` с cookie тестера | `200 OK` для списка и существующего id |
| AUTH-05B | Административные производители | `GET /api/admin/materials/manufacturers` и `GET /api/admin/materials/manufacturers/{id}` с cookie тестера | `200 OK` для списка и существующего id |
| AUTH-06 | Изменения без авторизации | `POST`, `PUT`, `DELETE`, сортировка без cookie | `401 Unauthorized` |
| AUTH-07 | Список административной панели без авторизации | `GET /api/admin/materials` без cookie | `401 Unauthorized` |
| AUTH-07A | Чтение административных справочников | Вызвать списки и карточки `/api/admin/materials/{categories,sheet-sizes,manufacturers,thicknesses}` без cookie, с cookie обычного пользователя и с разрешёнными ролями | Соответственно `401`, `403`, `200` для существующих записей |
| AUTH-08 | Закрытый метод от имени менеджера | Выполнить разрешённый закрытый запрос с cookie пользователя с ролью `manager` | Успешный ответ |
| AUTH-09 | Закрытый метод от имени администратора | Выполнить разрешённый закрытый запрос с cookie пользователя с ролью `admin` | Успешный ответ |
| AUTH-10 | Закрытый метод от имени обычного пользователя | Выполнить закрытый запрос с cookie пользователя без ролей `tester`, `manager` и `admin` | `403 Forbidden` |
| AUTH-11 | Закрытый метод от имени тестера | Выполнить разрешённый закрытый запрос с cookie пользователя с ролью `tester` | Успешный ответ на тех же административных endpoints, что у менеджера и администратора |
| AUTH-12 | Очистка тестовой истории | Вызвать `DELETE /api/admin/catalog/history/test-runs/{runId}` анонимно, обычным пользователем, менеджером, администратором и тестером; от имени тестера также передать `runId` неверного формата | Анонимный запрос возвращает `401`; обычный, менеджер и администратор — `403`; тестер с корректным `runId` — `200`, с некорректным — `404` из-за route constraint `int` |

## SEARCH — поиск и пагинация

Запросы выполняются анонимно к `GET /api/materials/search`. Сохранить таблицу входных значений и id; ожидаемые множества вычислять по этой таблице, а не по ответу проверяемого API. Ограничивать выдачу параметром `search=<маркер>`. Данные между страницами не изменять. Каждый вариант параметризованного кейса проверять отдельно.

## THICK — справочник толщин и связь с материалом

Данные создаются тестером с уникальным префиксом. Для числового значения новой толщины использовать уникальную положительную дробь; существующие толщины не менять. После проверки удалить материалы, затем созданные справочники. Все кейсы включены в HTTP-раннер.

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| THICK-01 | Создать толщину с name и value; получить административные список и карточку | 200, id/name/value совпадают; список отсортирован по value |
| THICK-02 | Создание анонимом и обычным пользователем; PUT/DELETE теми же ролями; сохранение без изменений тестером, менеджером, администратором | 401/403 для запрещённых операций, 200 для разрешённых, данных и истории не прибавилось |
| THICK-03 | POST/PUT: отсутствующие поля, пустое имя, пробелы, 101 символ, value 0/-1/NaN/Infinity, более трёх знаков после десятичной точки, дубликат значения; GET/PUT/DELETE с id 0/-1/неизвестным | 400 ProblemDetails, существующая запись не изменена |
| THICK-04 | PUT имени длиной 100; затем имени с пробелами по краям, сохраняя value; затем изменить value с шагом 0.001; проверить значения с 0–3 знаками после точки | 200, имя обрезано по краям, новое имя и value сохранены |
| THICK-05 | Создать материал с thicknessId; проверить две карточки и три списка, фильтры `/api/materials/search`; удалить используемую толщину; POST/PUT материала с неверной толщиной | В ответах вложенный thickness с id/name; фильтр возвращает точные id; неверные ID и удаление используемой записи дают 400 |
| THICK-06 | Повтор thicknessIds, совместно с несовпадающим depths; выбранная толщина без подходящих материалов в фасетах | Нет дублей; depths и thicknessIds пересекаются; фасет игнорирует собственный фильтр, сохраняет выбранный вариант с count=0 |
| THICK-07 | Удалить материал и свободную толщину; повторить GET; проверить историю по префиксу | Удаление 200, чтение 400, тестовые записи удалены, история тестера отсутствует |
| THICK-08 | Менеджером создать толщину с маркером HIST-прогона, изменить только имя, повторить PUT, удалить | Ровно Create/Update/Delete, Update содержит только изменённое имя, инициатор корректен; тестер удаляет историю по runId |

## CALC — контракт материалов для CalculateAPI

Отдельные endpoints `GET /api/calculate/material-categories` и `GET /api/calculate/materials?categoryId=…` требуют cookie пользователя с ролью `manager`, `admin` или `tester`. Основные сценарии выполняются тестером. Категории возвращают `items` с `id` и `name`; материалы — `items` с `id`, `name` и `article`. Порядок обоих списков: `OrderByCol`, затем `Id`. Дополнительных фильтров и пагинации нет.

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| CALC-01 | Контракт OpenAPI | Получить `/swagger/v1/swagger.json`, проверить оба новых пути и схемы `GetMaterialCategoriesForCalculateQueryResult`, `GetMaterialCategoriesForCalculateQueryItem`, `GetMaterialsForCalculateQueryResult`, `GetMaterialsForCalculateQueryItem` | У категорий нет query-параметров; у материалов единственный обязательный параметр `categoryId` типа integer. Поля схем имеют ожидаемые типы, русские описания и обязательность; ответы списков используют `items`, элементы категорий ссылаются на `GetMaterialCategoriesForCalculateQueryItem` |
| CALC-02 | Категории, включая скрытые и пустые | Подготовить видимую, скрытую и пустую тестовые категории, получить `/api/calculate/material-categories` | Все три категории присутствуют, порядок совпадает с каталогом |
| CALC-03 | Все материалы только одной категории | В тестовых категориях подготовить скрытый материал, материал с нулевым количеством, материал с `applicableToCutting=false` и материал в скрытой категории. Получить `/api/calculate/materials?categoryId=…` для каждой категории | Возвращаются все материалы выбранной категории в порядке каталога, независимо от видимости, наличия и применимости к распилу; материалы других категорий отсутствуют |
| CALC-04 | Обязательность и существование категории | Вызвать список материалов без `categoryId`, с пустым, нечисловым, нулевым, отрицательным и заведомо неизвестным положительным значением | Каждый запрос возвращает `400` в формате ProblemDetails; отсутствующая категория не превращает запрос в выдачу всех материалов |
| CALC-05 | Существующая пустая категория | Получить материалы существующей категории без материалов, в том числе скрытой | `200` и `{ "items": [] }` |
| CALC-06 | Авторизация | Вызвать оба endpoint без cookie, обычным пользователем и тестером; для списка материалов передать существующую категорию | Без cookie — `401`, обычный пользователь — `403`, тестер — `200` |

После проверки удалить созданные тестовые материалы и справочники. Существующие публичные и административные URL каталога сохраняются.
