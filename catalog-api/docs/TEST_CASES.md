# Тест-кейсы Catalog API

## Контекст

- Авторизация менеджера: Accounts API, `POST /api/sign/in`.
- Публичные чтения: материалы, категории, карточки и изображения.
- Авторизация cookie требуется для чтений административной панели и всех изменений данных.
- Все enum в JSON передаются и возвращаются строковыми именами, а не числами: например, `"direction": "UP"` и `"countTypeEnum": "M2"`.

## PREP — подготовка

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| PREP-01 | Получить cookie менеджера | Авторизоваться через Accounts API | Успешный ответ, клиент получил `AccountsApiCookie` |
| PREP-02 | Подготовить авторизованный клиент | Открыть Scalar Catalog API в том же профиле либо использовать HTTP-клиент с cookie | Cookie отправляется в закрытые запросы |
| PREP-03 | Подготовить неавторизованный клиент | Использовать инкогнито-окно либо клиент без cookie | Запросы выполняются без cookie |

|---|---|---|---|

| AUTH-03 | Публичная карточка материала | `GET /api/materials/{id}` без cookie | `200 OK` для существующего id |

| AUTH-07 | Список административной панели без авторизации | `GET /api/materials/admin` без cookie | `401 Unauthorized` |

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| CAT-01 | Создание категорий | Трижды вызвать `POST /api/materials/categories` | Все запросы успешны, получены id |

| CAT-05 | Сортировка вверх | Поднять среднюю категорию | Она меняется местами с предыдущей |
| CAT-06 | Сортировка вниз | Опустить категорию | Она меняется местами со следующей |
| CAT-07 | Верхняя граница сортировки | Поднять первую категорию | Бизнесовая ошибка |

## IMG — загрузка изображений

Загруженное, но ещё не привязанное изображение сохраняется в таблице `image_cache`. Полученный GUID передаётся в поле `image` при создании или обновлении материала; тогда файл переносится в таблицу `material_images`. При чтении изображение бессрочно кэшируется в памяти процесса. Кэш очищается при перезапуске API, а также инвалидируется при замене или удалении изображения.

| ID | Сценарий | Шаги | Ожидаемый результат |
|---|---|---|---|
| IMG-01 | Доступ к загрузке | Отправить `POST /api/materials/images` без cookie | `401 Unauthorized` |
| IMG-02 | Допустимые форматы | Загрузить PNG, JPEG и WebP через multipart-поле `file` | Для каждого файла `200 OK`; возвращены GUID и корректный `contentType` |
| IMG-03 | Валидация загрузки | Отправить пустой, слишком большой или неподдерживаемый файл | `400 Bad Request` с понятной ошибкой |
| IMG-04 | Сохранение загруженного файла | Загрузить изображение и проверить запись по возвращённому GUID в `catalog.image_cache` | В таблице сохранены GUID, имя, MIME-тип и исходные байты файла |
| IMG-05 | Загруженный файл переживает перезапуск | Загрузить изображение, перезапустить API и вызвать `GET /api/materials/images/{fileGuid}` | `200 OK`, корректный `Content-Type`, файл совпадает с исходным |
| IMG-06 | Создание материала после перезапуска | Загрузить изображение, перезапустить API и передать его GUID при создании материала | Материал создан без зависимости от состояния memory cache; GUID указан в карточке материала |
| IMG-07 | Перенос изображения при создании | Создать материал с GUID из `image_cache`, затем проверить обе таблицы | Изображение находится в `material_images` и отсутствует в `image_cache` |
| IMG-08 | Привязка изображения при обновлении | Загрузить новое изображение и передать его GUID в `PUT /api/materials/{id}` | Новое изображение перенесено в `material_images`, удалено из `image_cache` и возвращается через публичный endpoint |
| IMG-09 | Прогрев memory cache | Очистить memory cache перезапуском API, дважды запросить одно изображение и проверить SQL-логи | Первый запрос читает БД, второй возвращает изображение без повторного SQL-запроса |
| IMG-10 | Бессрочное хранение в memory cache | После прогрева выполнить повторный запрос позднее, не перезапуская API и не изменяя материал | Изображение возвращается из memory cache; у записи нет абсолютного или скользящего срока истечения |
| IMG-11 | Инвалидация при замене | Сначала запросить старое изображение, затем заменить его через `PUT` и запросить старый и новый GUID | Старый GUID возвращает ошибку «Файл не найден»; новый GUID возвращает актуальное изображение и уже записан в memory cache |
| IMG-12 | Инвалидация при удалении | Сначала запросить изображение, затем удалить материал и повторить запрос по GUID | Удалённое изображение не выдаётся из memory cache; endpoint возвращает ошибку «Файл не найден» |
| IMG-13 | Восстановление memory cache после перезапуска | Прогреть кэш, перезапустить API и дважды запросить сохранённое изображение | Первый запрос после запуска читает `material_images`, второй обслуживается из memory cache |

## VAL — валидация

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| VAL-01 | Пустые обязательные поля | `400 Bad Request` с понятной ошибкой |
| VAL-02 | Нулевая или несуществующая категория | `400 Bad Request` |
| VAL-03 | Нулевые/отрицательные размеры, площадь, периметр, толщина | `400 Bad Request` |
| VAL-04 | Цена `<= 0` при количестве больше нуля | `400 Bad Request` |
| VAL-05 | Не включён ни один калькулятор | `400 Bad Request` |
| VAL-06 | Дублирующееся название материала | `400 Bad Request` |
| VAL-07 | Несуществующий id материала или категории | Корректная ошибка API |
| VAL-08 | Недопустимое направление сортировки | Корректная ошибка API |
| VAL-09 | Несуществующий GUID изображения | Корректная ошибка API |
