# Инструкции для AI-агентов

## Миграции базы данных

- AI-агент может создавать и изменять файлы Entity Framework Core migrations, если это требуется задачей.
- AI-агент не должен выполнять миграции на какой-либо базе данных (`dotnet ef database update` и аналогичные команды).
- Все миграции пользователь применяет вручную.
- После создания миграции агент должен проверить сборку проекта и сообщить пользователю имя созданной миграции.

## Тестирование

- Стабильные сценарии ручного тестирования находятся в `catalog-api/docs/TEST_CASES.md`. Не добавляйте туда результаты конкретных прогонов, даты, временные блокировки и найденные дефекты.
- Перед функциональным прогоном проверьте соответствие отслеживаемых текстовых файлов правилам корневого `.editorconfig`, включая форматирование C#, кодировку UTF-8 без BOM и окончания строк LF.
- `catalog-api/docs/TEST_EXECUTION.md` должен содержать только результат последнего прогона. При новом прогоне полностью заменяйте предыдущий отчёт; историю прогонов в этом файле не накапливайте.
- Для DEV-контура можно отключать проверку TLS-сертификата, например через `curl --insecure`. Для production-контура проверку TLS не отключайте.
- Для DEV-авторизации используйте служебные данные из `catalog-api/docs/TEST_CREDENTIALS.md`.
- Не сохраняйте в документации значения cookie, токены и другие полученные секреты.
- Перед авторизованными сценариями получите `AccountsApiCookie` через Accounts API. Если авторизация или Accounts API недоступны, не выполняйте зависимые сценарии и зафиксируйте блокировку в `TEST_EXECUTION.md`.
- После тестового прогона удаляйте созданные тестовые сущности и временные файлы.

## Дефекты

- Подтверждённые проблемы регистрируйте в `catalog-api/docs/DEFECTS.md`.
- Один дефект оформляйте одной записью с постоянным идентификатором `DEF-###`.
- В `TEST_EXECUTION.md` указывайте идентификатор связанного дефекта.
- После исправления и успешного ретеста удаляйте подробную запись из раздела «Открытые дефекты» и добавляйте в «Историю исправлений» краткую строку `DEF-### исправлен`.
- Не переносите в историю полное описание, шаги и результаты исправленного дефекта.
